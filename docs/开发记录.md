## 需求演进

### v1 —— 单文件 HTML

最初的需求是一个"可直接双击打开的网页"：标题「上班鼓励器」、右上角设置按钮、实时日期星期时间、上下班状态、距下班倒计时、今日已赚（元，4 位小数）、赚钱速度（元/秒，4 位小数）、自动鼓励语「再过 X 小时 X 分，一件 T恤就赚回来了」、关闭计时器按钮，以及今日工时进度、本月累计、时薪、今日满勤可得。

**结论**：满足需求，但不够。真正有用的形态是常驻桌面的小挂件，而不是一个需要切标签页的网页。

### v2 —— 改成真正的桌面 exe

用户明确指出：

> 「就是个纯粹的网页嘛？不是应该是个 exe，然后点击有点透明度，可以悬浮在所有窗口上层，可以任意拖动嘛？」

技术选型 **WPF (net10.0-windows)** 原生实现，没用 Electron —— 避免 ~200 MB 的依赖下载，最终单文件产物只有 ~280 KB。

### v3 —— 改按月薪折算

用户纠正了两点：

> 「你得透明度应该也有设置才对。我可以拖动透明度，还有窗体大小也可以改变，可以做到比较低级的适配」
> 「应该按月薪填写啊。还有修改了月薪，上班下班时间，就应该里面重算。上下班时间，先按 9 点，6 点算。国家法定的一个月上多少天，我记得差不多 21.5 天算？」

**关于 21.5**：用户的记忆是民间说法。法定的**月计薪天数是 21.75**（(365 − 104) ÷ 12 = 21.75）；另一个常被混用的数字是「月工作日 20.83 天」（扣除 11 天法定节假日）。折算日薪/时薪的标准基数是 **21.75**。

## 关键实现与踩坑

### 透明窗口的缩放边框：`WindowChrome` 在 `AllowsTransparency=True` 下无效

`AllowsTransparency=True` 的窗口是**分层窗口**，没有非客户区（non-client area），而 `WindowChrome` 的 `ResizeBorderThickness` 正是画在非客户区上的 —— 所以它一点作用都没有，鼠标移到边缘根本拖不动。

无效的尝试：
- `GIT_SSL_NO_REVOKE=1`、`http.schannelCheckRevoke=false` —— 这是 TLS 的问题，与此无关
- `http.sslBackend=openssl` —— 只是换成另一种报错

**解法**：自己画 8 个缩放热区，鼠标按下后手动改 `Width/Height/Left/Top`。

```xml
<Rectangle x:Name="GripLeft" Style="{StaticResource ResizeGrip}"
           Width="12" HorizontalAlignment="Left" Cursor="SizeWE" />
```

四个细节：
1. **热区必须放在 `WindowRoot` 的最外圈**（`RootGrid` 的 16px `Margin` 内），否则会盖住设置面板里的按钮
2. **`PointToScreen` 返回物理像素，窗口尺寸用的是 DIP** —— 必须除以 `VisualTreeHelper.GetDpi(this).DpiScaleX`，否则高分屏上缩放速度会快好几倍
3. 拖左边/上边时，要同步调整 `Left/Top`，保证锚点那一侧不动
4. 尺寸要夹在 `MinWidth/MinHeight` 与 `MaxWidth/MaxHeight` 之间，越界时把对边拉回来

### 暂停时数字还在跳

原始代码里有一处**无效三元组**：

```csharp
DateTime effNow = paused ? now : now;   // 两个分支都是 now
```

于是暂停期间 `GetElapsedWorkSeconds(baseDate, now)` 仍随墙上时钟增长 → 今日已赚继续涨、进度条继续走、距下班倒计时继续减。更糟的是 `todayRec.Earned = st.Earned` 把这个错误的增长值写进了 CSV。

**解法**：`Compute` 增加 `pausedAt` 参数，暂停时以"暂停那一刻"为基准：

```csharp
DateTime effNow = now;
if (paused && pausedAt.HasValue)
{
    effNow = pausedAt.Value;
    if (effNow.Date != baseDate) baseDate = effNow.Date;   // 跨天暂停用暂停当天的作息
}
```

配套还要修**暂停时长的计量口径**：原来恢复时累加的是墙上时钟秒数 `(now - _pauseAt)`，如果暂停横跨午休就会多扣工时。改成只累加真正落在工作时段内的部分：

```csharp
_pausedAccumSec += _schedule.GetElapsedWorkSeconds(from.Date, to)
                 - _schedule.GetElapsedWorkSeconds(from.Date, from);
```

### 端到端测试逼出来的三个真 bug

这三个都是纯逻辑测试发现不了、只有把"模拟一整天"跑起来才会暴露的问题：

1. **暂停时段工时整段丢失**
   暂停区间被完全跳过。修复：切暂停前先用 `paused=false` 结算到暂停时刻。
   > `WorkdayTracker.Advance` 的 `paused` 语义是"这一整段都没在上班"，所以必须先结算再切状态。

2. **历史日期"应出勤工时"永远为 0**
   之前只有界面层给当天赋值。修复：`WorkdayTracker.Advance` 自己计算并写入 `rec.ScheduledSec`，否则 CSV 的"应出勤"列全是 0。

3. **跨夜工时全记到当前日**
   原来把跨夜区间整段记到今天。修复：`Advance` 按自然日切分循环，逐日归属。

### 界面适配技巧

- **数字防跳动**：`FontFamily="Consolas"` + `Typography.NumeralAlignment="Tabular"`
- **等比缩放**：`<Viewbox Stretch="Uniform">` 包住固定设计宽度 424 的内容，窗口任意缩放内容等比变化（矢量清晰不糊）
- **窗口必须** `SizeToContent="Manual"` + 固定 `Width/Height` + `ResizeMode="CanResize"`，否则高度被内容锁死
- **自检不用外部截屏工具**：给程序加 `--shot <png>` 参数，用 `RenderTargetBitmap` 自己导出窗口截图；配合 `--size 宽x高`、`--open-settings`、`--open-stats` 验证各种状态

### 企业网络下的 Git 推送（TLS 中间人）

现象：`git push` 报 `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`，但 `gh api` 一切正常。

**根因**：环境里有 HTTPS 代理（公司 VPN 的 Cato Networks 客户端），它做 TLS 中间人，签发 `CN=Cato-Networks-Server-*` 中间证书，而**吊销检查（CRL/OCSP）被 VPN 阻断**。
- `gh` 用 Go 的 `crypto/x509`，走系统证书库 → 没事
- git 自带 CA bundle 不认企业 CA → 失败

**解法**（没有用 `sslVerify=false` 降级，证书校验完整保留）：

```bash
# 1. 从 Windows 证书存储导出企业 CA
Get-ChildItem Cert:\CurrentUser\Root, Cert:\LocalMachine\Root |
  Where-Object { $_.Subject -like "*Cato*" } | ForEach-Object {
    "-----BEGIN CERTIFICATE-----`n" + [Convert]::ToBase64String($_.RawData,"InsertLineBreaks") +
    "`n-----END CERTIFICATE-----`n" } | Set-Content C:\Users\zdhzh\.gitcerts\cato-ca.pem -Encoding ascii

# 2. 与 git 默认 bundle 合并
cat "/c/Program Files/Git/usr/ssl/certs/ca-bundle.crt" \
    /c/Users/zdhzh/.gitcerts/cato-ca.pem > /c/Users/zdhzh/.gitcerts/combined-ca.pem

# 3. 写全局配置
git config --global http.sslBackend openssl
git config --global http.sslCAInfo "C:/Users/zdhzh/.gitcerts/combined-ca.pem"
```

之后 `git clone / push / pull` 全部正常。

**另外**：本机 `~/.ssh/id_ed25519` 没在 GitHub 账号登记，`ssh -T git@github.com` → Permission denied (publickey)，所以走不了 SSH 通道。
