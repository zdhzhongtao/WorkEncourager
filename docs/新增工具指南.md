# 新增工具指南

从「有个想法」到「同事能双击用」，标准动作五步。全程不需要改任何已有工具的代码。

---

## 第 0 步：先回答三个问题

动手前先把这三句写下来，写不出来就说明还没想清楚：

1. **谁会用？** 具体到人。「我自己」也算，但那就别做设置页了。
2. **他现在怎么干的？** 手动步骤有几下？超过 3 下才值得自动化。
3. **做完之后他少做哪几步？** 说不清「省掉了什么」，就是伪需求。

> 反面教材：做一个「用 AI 总结会议纪要」的工具，但公司开会不给录音。需求真实存在，前提不成立。

---

## 第 1 步：复制模板

```bash
# 在库根目录执行
cp -r src/_template src/<ToolName>
```

把文件夹名换成工具的英文短名（PascalCase，不要空格不要中文），比如 `TableDiff`、`FileRenamer`、`ExpenseSplit`。

## 第 2 步：改名与项目配置

打开 `src/<ToolName>/<ToolName>.csproj`，改四个地方：

```xml
<AssemblyName>TableDiff</AssemblyName>       <!-- 发布出的 exe 名 -->
<RootNamespace>TableDiff</RootNamespace>     <!-- 代码命名空间 -->
<Product>表格差异对比</Product>               <!-- 中文产品名，显示在界面和文件属性里 -->
<Version>0.1.0</Version>                     <!-- 新工具从 0.1.0 开始 -->
```

同时改 `App.xaml` 和 `MainWindow.xaml` 里的 `x:Class`、`xmlns:local`，以及两个 `.cs` 的 `namespace`。

## 第 3 步：改数据目录

模板里数据目录常量是这样写的：

```csharp
static readonly string DataDir = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData),
    "ToolTemplate");   // ← 改成你的产品名，比如 "TableDiff"
```

**这一行必须改**，否则两个工具会写到同一个目录，互相覆盖配置。

## 第 4 步：登记

两个地方各加一行，缺一个就会「VS 里找不到项目」或者「同事不知道有这个工具」：

**a) 库根 `WadeToolbox.slnx`** —— 加在 `src/<ToolName>/` 这个 Folder 下：

```xml
<Folder Name="/src/TableDiff/">
  <Project Path="src/TableDiff/TableDiff.csproj" />
  <Project Path="src/TableDiff/TableDiff.Tests/TableDiff.Tests.csproj" />
</Folder>
```

**b) 库根 `README.md` 的工具清单表** —— 加一行，状态填 🚧 开发中。

**c) `src/<ToolName>/docs/`** —— 建两份，命名跟 WorkEnc 保持一致：
- `使用说明.md`：界面长什么样、每个设置项什么意思、数据存在哪
- `开发记录.md`：为什么这么设计、踩了什么坑（三个月后你会感谢自己）

## 第 5 步：CI（可选，但强烈建议）

复制 `.github/workflows/ci-workenc.yml` 为 `.github/workflows/ci-<toolname>.yml`，把所有 `src/WorkEnc/` 路径替换成你的路径。

如果这个工具暂时不想自动发版，把 `release` 那段整个删掉，只留编译 + 测试。

---

## 写代码时的检查清单

**必须做到：**

- [ ] 数据写 `%APPDATA%\<产品名>\`，不是程序目录，不是仓库目录
- [ ] 写文件用「临时文件 → 原子替换 → `.bak` 备份」（参考 `src/WorkEnc/WorkEnc.Core/AtomicFile.cs`）
- [ ] 界面上有明确的「真正退出」入口，`×` 可以只是隐藏
- [ ] 任何耗时操作（读大文件、算几万行）不阻塞 UI 线程
- [ ] 出错时给中文提示，不弹英文异常堆栈
- [ ] 首次运行不需要任何配置就能看到有意义的结果

**不要做：**

- [ ] 不要弹「请先配置数据库连接」这类前置门槛
- [ ] 不要强制联网激活 / 登录 / 上报统计
- [ ] 不要依赖第三方 UI 控件库（体积大、许可麻烦、升级会炸）
- [ ] 不要为了「以后可能用得上」加用不到的抽象层

---

## 发布一个版本

```bash
# 框架依赖包里约 280 KB，机器需要装 .NET 10 Desktop Runtime
dotnet publish src/<ToolName>/<ToolName>.csproj -c Release -r win-x64 \
  --self-contained false -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true

# 自包含包约 80 MB，任何 Win10/11 机器双击就跑
dotnet publish src/<ToolName>/<ToolName>.csproj -c Release -r win-x64 \
  --self-contained true -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true
```

发给同事时优先给自包含版——他们不会为了你的工具去装运行时。
