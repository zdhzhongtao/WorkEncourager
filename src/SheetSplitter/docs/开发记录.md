# 表格拆合器 · 开发记录

> 使用说明见 [使用说明.md](使用说明.md)。

---

## 需求

财务月结的四个重复劳动：

1. 一张总表按部门拆成 12 个文件发出去
2. 12 个月的表合成一张年度表
3. 一个工作簿里的分月 sheet 合成一张
4. 一张大表按行数切开分批发邮件

规格书第 6 节另外压了几条硬约束：源文件只读不写、输出重名不覆盖、先 `.tmp` 再改名、失败不留半个文件、执行前要能预判「生成几个文件」。

## 架构

```
SheetSplitter.exe
  MainWindow.xaml        四个模式（TabControl）+ 共用底部操作条
  MainWindow.xaml.cs     全部交互（读文件、建计划、执行）
  PreviewWindow.xaml     预览源表前 100 行
SheetSplitter.Core
  TableReader / ExcelReader / CsvReader / SheetData / CellText   ← 从 TableDiff 复制
  SplitPlanner           三种计划：按列值 / 合并 / 按行数
  SplitExecutor          把计划落盘，单个失败不影响其余
  ExcelWriter            写 xlsx（先 .tmp 再改名）
  FileNameSanitizer      文件名清洗 + 重名加序号
SheetSplitter.Tests      47 个用例
```

**读表代码是复制过来的**（`TableReader` / `ExcelReader` / `CsvReader` / `SheetData` / `CellText` / `AtomicFile` / `Theme`），只改了命名空间。规矩就是规矩：不 `ProjectReference` 到 TableDiff，也不回头改 TableDiff。代价是以后修 TableDiff 的读表 bug 要手动同步两份——这是这套库明确接受的成本（见 `docs/库结构说明.md`）。

## 关键决策

### 1. 「计划」与「执行」分离

`SplitPlanner` 只算「要生成哪些文件、每个文件哪些行」，不碰磁盘；`SplitExecutor` 才写。好处有三：

- 「预览」功能天然成立：跑一遍 planner 就能报「将生成 13 个文件，共 500 行」
- 可以单测：47 个用例里 30 个只测 planner，不需要磁盘
- 用户可以看着清单决定要不要真执行

### 2. 按列值分组用「首次出现顺序 + 空白组垫底」

用 `Dictionary` 分组会丢顺序（.NET 虽然实际保序，但语义上不承诺）。所以显式维护一个 `List<string> order` 记录首次出现顺序，空白单独一组放最后——用户扫文件名时顺序稳定，不会每次跑都变。

### 3. 表头对齐：union + 记录缺列

合并时把各表的列名取**并集**（大小写不敏感），第一个文件里的列顺序优先，后面的新列追加到末尾。缺的列留空格子，同时生成 `a.xlsx - 缺列：金额` 这样的说明。

第一版想的是「以第一张表为准，多出来的列丢掉」，但那会**悄悄丢数据**——比多一列难查得多。

### 4. 按位置对齐时列名统一成「列1 列2」

按位置对齐时两边列名往往不一样（`单号` vs `编号`），不能任选一边的名字。统一成 `列N` 最不容易误导。

### 5. 文件名清洗在「拼完之后」再兜一次长度

单洗值、单洗原名都不够：两个各 50 字的字符串拼起来还是超长。`BuildFileName` 拼完再看总长度，超了截断到 60。Windows 的 260 字符路径上限在小工具里不值得精确计算，留足余量更省事。

### 6. 输出重名靠「本次运行内集合 + 磁盘存在性」双重判断

只看磁盘会漏掉「同一批里两个文件撞名但第一个还没写完」的情况（模式 1 里如果两个部门名清洗后变一样，就会撞）。所以 `ResolveUnique` 既查 `File.Exists`，也查本次运行已用过的名字集合。

### 7. 写 xlsx 时把「像数字的」写成数字

如果全写成文本，Excel 会给每一格挂绿色小三角（「以文本形式存储的数字」），用户会以为出错了。所以写之前 `double.TryParse` 一下，能解析且首位不是 `0` 就写数字——`007` 这种要保留前导零的仍然写文本。

## 踩过的坑

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 测试里「重名加序号」只加到 (1) 就停了 | 测试只写了第一个文件，第二个文件还没落盘，第三次调用当然还是 (1) | 测试里把第二个也写出来 |
| ClosedXML `SaveAs` 后 `File.Move` 偶尔报占用 | 句柄在 `using` 结束前没释放 | `SaveAs` 到 `.tmp.xlsx`，`using` 块结束后再 `Move` |
| sheet 名里有 `/` 时保存抛异常 | Excel 不允许 `[ ] : * ? / \` | `SheetName.Safe` 统一替换 + 截断 31 字 + 重名加 (2) |
| 按行数拆分填 0 会死循环 | `for (start += 0)` | planner 里先校验 `rowsPerFile > 0` |
| 合并 100 万行时程序直接崩 | 超过 xlsx 单表上限 | planner 里提前算总行数并抛中文错误 |

## 测试

47 个用例：

| 分组 | 覆盖 |
| --- | --- |
| 文件名清洗 | 非法字符、空值、首尾空格点、超长、纯中文、拼完总长度、重名 (1)(2)、同批内重名 |
| 按列值分组 | 组数与成员、空白组垫底、单值、含空格与点、列下标越界、保留/不保留表头、拆成多 sheet、空表 |
| 合并 | 按列名对齐（列序不同）、缺列留空并记录、多列追加、按位置对齐、来源两列、空输入、结果 sheet 名 |
| 按行数 | 整除、余 1、N 大于总数、0 行、非法 N、超 Excel 上限、文件名序号、每份带表头 |
| 执行 | 写后能读回、不留 `.tmp`、重名不覆盖、没选目录报错、执行前不产生文件、源文件未被改动 |
| 验收链路 | 500 行 → 拆 13 个 → 全部读回 → 合回 500 行 → 单文件翻倍合并 → 按 100 行切 5 份 → 源文件字节与时间戳不变 |
