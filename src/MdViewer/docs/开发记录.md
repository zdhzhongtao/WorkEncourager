# Markdown 阅读器 · 开发记录

> 记这个工具怎么做出来的、为什么这么选，以及踩过的坑。
> 使用说明见 [使用说明.md](使用说明.md)。

---

## 需求

一句话：**替代「用 VS Code 看 md」**。双击 `.md` 直接打开，排版好看（类 GitHub 但更舒服）、左边目录、页面内搜索、导出 PDF、浅深两套主题。

规格书定死的东西（不能改）：Markdig 解析、WebView2 渲染、内联 HTML 要清洗、WebView2 用户数据目录设到 `%APPDATA%\MdViewer\WebView2`、只写 HKCU 做文件关联。

## 几个关键决策（以及为什么）

### 1. 渲染链路顺序：Markdig → 清洗 → 任务列表 → 补 id

顺序不能换。清洗必须在「补标题 id」之前，否则 md 里写死的 `onclick` 会跟着标题一起进页面；反过来先补 id 再清洗的话，正则会误伤刚生成的 `id="..."`。

### 2. 不用 `<base href>`，改成把相对地址直接改写成虚拟域名

一开始用「映射目录 + `<base>`」的经典做法，结果撞上一个死结：有了 `<base>` 以后，md 里的 `[跳到表格](#表格)` 会被浏览器拼成 `https://md1.local/#表格`——跨文档导航，页面内跳转直接废掉。

改成：渲染完之后把 `<img src>` 与 `<a href>` 里的相对路径**逐个改写成** `https://md1.local/xxx`，页面不带 `<base>`。这样：

- 图片正常加载（虚拟域名映射到 md 所在目录）
- 锚点链接仍是同文档跳转，原生滚动
- 相对 md 链接变成绝对 url，宿主在 `NavigationStarting` 里截住 → 自己打开目标文件

### 3. 页面不走 `NavigateToString`，写到 `%APPDATA%\MdViewer\cache\view-N.html` 再导航

两个原因：`NavigateToString` 有 2MB 上限，长文档会被截断；`about:blank` 源不是 secure context，`navigator.clipboard` 用不了（复制代码块会退化）。

现在页面源是 `https://mdviewer.tmp`（映射到 cache 目录），剪贴板 API 可用；每打开一次生成一个新文件名，避免浏览器缓存。

### 4. CSP 只放行虚拟域名与 `data:`，把「零联网」落到实现上

规格书要求不联网。md 里挂着 `![](https://xxx/a.png)` 时浏览器是一定会去拉的，所以在页面里写死 CSP：

```
default-src 'none'; base-uri 'none'; img-src https://md{seq}.local data:;
style-src 'unsafe-inline'; script-src 'unsafe-inline'; font-src data:
```

远程图片被挡 → `app.js` 的 error 处理给它加 `.img-failed`，显示虚线占位框 + alt。远程链接用户点了才交给系统浏览器，是用户主动行为。

### 5. 目录内/外两种图片策略

- 在 md 所在目录**之内**：改写成虚拟域名 url（省内存、大图不卡）
- 跳出目录**之外**（`../b.png`、`C:\别处\x.png`）：读成 `data:` base64 内联（上限 8MB，扩展名白名单）

只有这样才能在不把整个盘符映射给网页的前提下，让 `../b.png` 也显示出来。

### 6. 服务端的注册表写入留在主程序，Core 只产出「键值清单」

`FileAssociation.PlanRegister(exePath)` 返回 `Set / DeleteKeys / ConditionalClear` 三个纯数据列表，测试直接断言这些列表（含「路径带空格时 command 保留引号」「三个扩展名」「取消关联只删自己的键」）。真正 `Registry.CreateSubKey` 在 `FileAssoc.cs`，Core 保持可跨平台测试。

「取消关联」的关键点：扩展名键**不整棵删**，只在自己默认值还等于 `MdViewer.md` 时才清默认值与 `OpenWithProgids\MdViewer.md` 那一条——不动别人的 ProgId。

### 7. 第二个实例不许回写 settings.json

第一次跑单实例验证就撞上了：第二个进程拿到路径转发给已有窗口后退出，它的 `OnExit` 顺手把**自己启动时读到的旧配置**写回磁盘，刚好覆盖掉第一个进程刚写进去的「最近文件」。修法是加 `_isOwner` 标志，只有拥有主窗口的实例才保存配置。

### 8. 搜索用 WebView2 Find API，不用自己写高亮

`CoreWebView2.Find.StartAsync(options)` + `MatchCount` / `ActiveMatchIndex` 两个属性直接给出 `x/y`，`SuppressDefaultFindDialog = true` 把自带的搜索框关掉，用我们自己的搜索条。比自己用 JS 包 `<mark>` 可靠得多（不会破坏 DOM、不会跟代码块里的 `</mark>` 打架）。

### 9. 字号缩放走 `postMessage` 而不是重渲染页面

`Ctrl+加减` 只发一条 `{kind:'fontSize', payload:18}` 给页面，页面把 CSS 变量 `--md-font-size` 改掉。标题尺寸用 `em` 写在 CSS 里，于是整篇按比例缩放，不用重新解析 markdown。

## 踩过的坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `<embed src="y.swf">` 清洗后还在 | 「成对标签」正则要求有 `</embed>` | 补一条「没有闭合标签」的正则 |
| 图片/链接改写出来的 html 是坏的（`src="img/a.pnga.png"`） | 把 `Match.Index`（相对标签串）当成了相对整个 html | 抽出 `ReplaceAttr`，整个属性重写，别只替换值 |
| 单实例转发后「最近文件」丢了一个 | 第二个进程退出时回写旧配置 | 加 `_isOwner`，非主实例不落盘 |
| `--demo` 生成的样例点开图看不到 | 样例 md 里相对路径写的是 `images/demo.svg`，但样例只写了 md | 顺手把 `images/demo.svg` 一起生成 |
| GBK 保存的 md 打开全是问号 | 直接按 UTF-8 读 | `TextLoader` 按 BOM → 严格 UTF-8 → GB18030 依次尝 |

### 0.2.0 的五个坑（都真踩过）

1. **`New-Item -Force` 会清空注册表键的默认值** —— 安装脚本必须「先读后建」。这是「原关联没备份、`-KeepExisting` 失效」的真正原因；排查时先怀疑了取值写法，差点误判。
2. **`Get-ItemProperty -Name '(default)'` 在脚本里拿不到默认值** —— 用 `(Get-Item $key).GetValue('')`。
3. **`WScript.Shell.CreateShortcut` 写不了中文名** —— 这台机器开了 UTF-8 全局代码页，文件名变成 `???`、`Save()` 抛 "Unable to save shortcut"。改用 IShellLink P/Invoke（`Shortcuts.cs`）。
4. **调用 GUI 程序不会阻塞** —— `& $exe --make-shortcut $lnk` 立刻返回，紧接着 `Test-Path` 必然扑空，会误判成"创建失败"。改成轮询等文件落盘。
5. **`ColumnDefinition.MinWidth="140"` 会钳住宽度** —— 收起侧栏时宽度设 0 也留一条灰边，得把 MinWidth/MaxWidth 一起归零。

另：`--disable-gpu`、`--renderer-process-limit=1` 等 13 个 Chromium 参数实测无效（431MB → 422MB）。WebView2 的内存是架构决定的，别再花时间调参数。

## 0.3.0 的坑

1. **XAML 资源键重复会让程序启动即崩，且没有任何提示**。`Key in dictionary: 'KeyBadge' Key being added: 'KeyBadge'` —— 用 `Edit` 往 Styles.xaml 追加样式时把已有的 `KeyBadge` 又写了一遍；接着是隐式样式 `Separator`、`RadioButton` 各撞一次。三次都表现为「双击 exe 什么都不发生」。
   **定位手法**：`XamlParseException` 被 WPF 吞在 `App.InitializeComponent()` 里，日志都来不及初始化。把 `<OutputType>` 临时改成 `Exe` 用控制台跑一次，异常原文立刻出来，改回来只花十秒。比翻 WER 报告快得多。

2. **`RenderTargetBitmap` 截不到 WebView2**。它是原生子窗口，不走 WPF 渲染管线，`--snapshot` 出来的正文区永远空白（0.1.0 起就有这个盲区，一直靠人眼补）。这一版加了 `SnapshotPageAsync`，用 `CoreWebView2.CapturePreviewAsync` 单独截正文，`--snapshot` 会同时输出 `x.png` 和 `x.page.png`。自检终于能看见真实排版了。

3. **`FileSystemWatcher` 不能直接盯文件**。VS Code / Typora 保存时是「写临时文件 → 删原文件 → 改名」，盯文件句柄的写法第一次保存就失效。盯目录 + `Filter` 才稳；顺手接了 `Error` 事件，缓冲区溢出后自动重启监听。

4. **`CaptureScrollAsync` 会把「存档」和「还原」混淆**。切文档时先 `await` 取旧文档位置，异步回来时 `_restorePending` 被置 true，于是新文档用旧文档的比例跳转。加了个 `markForRestore` 参数分开两件事。

5. **EPUB 的章节 id 会互相撞车**。整本拼一页后，每章都可能有 `id="note1"`。统一加 `c<章号>-` 前缀，`href="#note1"` 同步改写；跨章链接（`ch2.xhtml`）直接变成页内锚点 `#c2`。

6. **EPUB 图片需要第二个虚拟域名**。正文页在 `mdviewer.tmp` 下，图片来自 `epub1.local`（映射解压目录），CSP 只写一个源会把图片全拦掉。`PageOptions.ExtraOrigins` 就是为这个加的，`img-src` 里列出全部来源。

7. **EPUB 里 `<style>` / `<link rel=stylesheet>` 必须剥掉**。`HtmlSanitizer` 是黑名单式的，不处理这两个标签；不剥的话书的样式会污染整页（尤其 `body{font-family:serif;margin:0}` 这种）。

8. **`settings.json` v1 → v2 迁移不能无条件做**。「RecentEntries 空就从 RecentFiles 迁」这条逻辑会让用户清空最近列表后又被旧字段填回来。改成只在 `Version < 2` 时迁移一次。

9. **运行中的 exe 可以同卷改名，但删不掉**。自动更新用「复制成 `.new` → 老的改名 `.old` → 新的就位 → 重启」，比批处理延迟替换可靠；`.old` 留给下次启动清理。

10. **`-p:EnableCompressionInSingleFile=true` 值得开**。自包含单文件 133MB → 62.5MB，启动多花约 0.3 秒。`local` 版再加上 `--self-contained false` + `IncludeNativeLibrariesForSelfExtract`，2.2MB 一枚 exe，没有任何附属文件。

11. **`AllowedReferenceRelatedFileExtensions=.pdb`** 能挡住 nuget 带过来的 `.xml` 文档（1.2MB 的无用文件原来会被一起 publish 出去）。

12. **深色模式下正文两侧一直露白，肉眼截图看不出来**。`body` 限宽 880px 且 `margin: 0 auto`，**正文两侧的空白是 `<html>`（画布）画的**；主题变量只定义在 `body.theme-dark` 上，`html` 拿到的仍是 `:root` 的 `#FFFFFF`，于是深色模式下左右各留一条白边。
   修法：主题类同时挂到 `<html>` 和 `<body>`（`html.theme-dark, body.theme-dark` 共享变量块），并补 `color-scheme: light|dark` 让 Chromium 按主题画滚动条与原生控件。
   **发现过程值得记一笔**：截图上看就是「有点白边」，判断不了严重程度。用 `CapturePreviewAsync` 出的 `.page.png` 逐像素采样才确认是纯 `#FFFFFF` —— 正文区 x∈[25,905) 是 `#1E293B`，两侧全白。Pillow 装不上（pip 超时）、`Add-Type` 被安全策略拦，最后用 `zlib` + PNG 滤波器手写 40 行解码器采样，反而最快。

13. **多工具共用同一个 GitHub 仓库时，`/releases/latest` 会取到别人的发布**。本仓库的 Release 里既有 WorkEnc 的 `v2.2.2`，将来也有 `mdviewer-v0.3.0`；`latest` 只看时间，很可能返回一个没有 MdViewer 附件的 Release，自动更新就永远「没有新版本」或者更糟——下载错程序的 exe。
   改成拉 `/releases?per_page=30` 自己挑：跳过 draft / prerelease，要求 **tag 名或附件名里带 `MdViewer`**，多个匹配取版本最高的那个。附件打分仍然是 `portable +4 > selfcontained +3 > 命中名字 +2`，保证自动更新拿到自带运行时的版本。
   解析逻辑抽成纯函数 `UpdateChecker.PickBest(json, current, hint)`，离线可测 —— 这类「挑错了也不报错、只是行为诡异」的逻辑，靠联网手点是测不出来的。

14. **`tag` 名不能直接当 `-p:Version`**。tag 是 `mdviewer-v0.3.0`，塞进 `-p:Version=` 会被判成非法版本号，CI 直接挂在 publish 那一步。加一个 `算版本号` 步骤剥前缀，非 tag 触发时回落到 csproj 里的版本。

15. **只读计算属性会被 `System.Text.Json` 写进文件**。`RecentEntry.OpenedTime` 是从 `OpenedAt` 解析出来的视图，序列化时把 getter 也写了一份，`settings.json` 里每条记录多一个永远不同步的 `OpenedTime` 字段。加 `[JsonIgnore]` 即可 —— 顺手补了条测试，断言文件里不出现这个键。

# 0.4.0：多主题 + 一轮问题清理

## 做了什么

| 主题 | 关键实现 |
| --- | --- |
| 10 套主题 | `MarkdownTheme` 清单（id / 名称 / 明暗 / accent / 预览色）+ `style.css` 里每套一块 `html[data-theme="<id>"]` 变量 |
| 换主题不重渲染 | `app.js` 的 `applyTheme` 只改 `<html data-theme data-mode>`；`BuildPage` 输出的初始值走同一套属性 |
| 界面配色派生 | `Theme.ForMarkdownTheme()`：按明暗取骨架，再覆盖 accent，并用 accent 与 CardBg 混出选中底色 |
| 浅深各选一套 | `settings.json` 加 `LightThemeId` / `DarkThemeId`（升到 v3），`EffectiveMarkdownTheme` 按模式 + 系统偏好挑 |
| 跟随系统实时 | `SystemEvents.UserPreferenceChanged` → BeginInvoke 回 UI 线程 → 只换配色不重渲染 |
| 工具栏主题面板 | Popup + 两个 ItemsControl（浅色组 / 深色组），色块预览 + 当前项打勾 |

## 关键决策

### 1. 主题变量只挂在 `<html>` 上

0.3.0 是 `html.theme-dark, body.theme-dark` 两个选择器共享一块变量，起因是踩过「只给 body 上色，正文两侧画布露白」。
变量本来就定义在 html 上，`html[data-theme="x"]` 命中 html、body 继承就够了，选择器少一半，也不会再有人只改一边。

### 2. 每套主题写全 28 个变量，不做「基底 + 差异」

试过把浅色公共 token 抽成一条多选择器规则、各主题只写差异。问题是 CSS 变量不跨选择器继承，
某套主题忘覆盖某个变量就会静默拿到别的主题的值 —— 这种 bug 只有肉眼能发现。
重复 280 行换来「改哪套就看哪块」，值。

### 3. 界面不给每套主题重做配色

`Theme` 有 36 个字段，10 套 × 36 = 360 个手写值，改一个色号要翻十处。
改成「按明暗取骨架 + 覆盖 accent」，`NavActiveBg` / `SelectionBg` 由 accent 与 CardBg 按比例混出来（`Theme.Mix`），
一套主题只需要管一个主色。浅主色（Nord 的 `#88C0D0`）还要把按钮文字换成深色，否则白字看不清 —— `Theme.ContrastOn` 按亮度判。

### 4. CSP 从 `'unsafe-inline'` 收紧到 nonce

`HtmlSanitizer` 是正则黑名单，天然有绕过面：事件属性正则要求前面是空白，`<img/onerror=alert(1)>` 就漏过去了。
页面脚本本来就是自己内联的，加个随机 nonce 就能把 `script-src 'unsafe-inline'` 换成 `'nonce-xxx'` ——
即使清洗漏了，注入的 script 也跑不起来。导出页同样锁 script，但放行图片与字体（导出的 md 常挂在线图）。

# 0.4.0：多列表格与宽屏

## 起因

一份 30 列的对照表，在默认 880px 正文栏里每格只能分到 26px —— 扣掉左右各 12px 内边距，
留给文字不到 3px，于是每格一个字一行，表格竖着长成一堵墙。横向滚动条也从来不出，因为
`table { width: 100% }` 让表格永远「不肯」超出容器：放不下就换行，滚动被换行替代了。

## 改法

| 位置 | 改动 |
| --- | --- |
| `style.css` `th, td` | 加 `min-width: 3.5em`。表格最小宽度变成「列数 × 下限」，放不下就交给外层滚 |
| `style.css` `.table-compact` | ≥8 列时内边距 12→8px、字号 0.91→0.86em，同屏多放几列 |
| `app.js` `wrapTables()` | 顺手数列数（取前几行最大值，兼容表头 colspan）写进 `data-cols`，≥8 列加 `table-compact` |
| `style.css` `body.wide` | 宽屏时左右留白 40→20px，屏幕才算真的用满 |
| `@media print` | 撤掉 min-width、`.table-wrap` 改 `overflow: visible`、字号降到 0.8em，宽表不撑出纸张 |

## 宽屏开关

工具栏「宽屏」（`Ctrl+Shift+W`）把 `--content-width` 发成 `none`，正文铺满窗口；
同时自动收起左侧目录 —— 收目录省下的 260px 比正文自身留白值钱得多。再点一下回到
设置里的宽度，目录恢复成用户原来勾选的状态（不动 `TocVisible` 这个设置本身）。

只推一条 `width` 消息给页面，不重渲染 —— 阅读位置不跳，来回切是瞬时的。

## 验证

- 用 Edge（WebView2 同款内核）无头模式量真实布局：30 列表格表宽 1710px、每格 51px、
  `scrollWidth > clientWidth` 成立，横向滚动条正常出现
- `dotnet test`：161 条全过（新增 2 条：宽屏页面输出 `--content-width: none` + `wide` 类、表格 CSS 契约）
- `--snapshot` 实拍：30 列窄栏出滚动条、12 列宽屏一屏放下不再折行、宽屏时目录收起且工具栏不挤

# 0.4.1：导出跟着宽屏走

## 问题

宽屏开着，导出的 html 还是锁在中间 880px 那条窄缝里；导出的 PDF 也是竖版 A4 —— 宽表在屏幕上刚铺开，一到纸上又被挤回竖条。

两处写死：

| 位置 | 原来 | 原因 |
| --- | --- | --- |
| `ExportHtml_Click` | `ContentWidth = (int)App.Settings.MaxContentWidth` | 只读设置里的宽度，压根没问 `WideMode`；也没给 body 挂 `wide` |
| `ExportPdf_Click` | 硬编码 `PageWidth=8.27 / PageHeight=11.69` | 只有竖版 A4 一种 |

## 改法

- 导出 HTML：`ContentWidth = ContentWidthForHost`（宽屏时是 0 → `--content-width:none`），
  `BodyClass = WideMode ? "wide" : null`。导出的页面跟屏幕上看到的一致：铺满，左右留白 20px。
- 导出 PDF：`WideMode` 时 `Orientation = Landscape`，否则 Portrait；宽高一律写竖版 A4。

### 坑：Orientation 会自己换宽高

一开始想「横版就把宽高写成 11.69 × 8.27」，结果和 `Orientation=Landscape` 一起写会**换两次**，又变回竖版。
用 WinForms + WebView2 写了个探针实测三种组合（读 PDF 的 `/MediaBox`）：

| 写法 | MediaBox | 结果 |
| --- | --- | --- |
| 只交换宽高（11.69 × 8.27），Orientation 默认 | 841.92 × 594.96 | 横向 ✅ |
| `Orientation=Landscape` + 竖版宽高（8.27 × 11.69） | 841.92 × 594.96 | 横向 ✅（与上一行字节完全相同） |
| 两者都按横版写 | 594.96 × 841.92 | 竖版 ❌ |

所以最终只动 `Orientation`，宽高保持竖版 A4。

## 验证

- `dotnet test`：162 条全过（新增 1 条：宽屏导出页同时带 `for-export` 与 `wide`、`--content-width:none`）
- PDF 方向用探针实测 MediaBox，不靠肉眼

# 0.4.3：恢复默认设置

## 起因

设置改来改去，想回到「刚装好那样」只能自己去翻 `settings.json` 或者删掉它 ——
删掉又连最近打开、阅读位置一起没了。

## 改法

设置窗口加「重置 → 恢复默认设置」，二次确认后：

| 恢复 | 保留 |
| --- | --- |
| 明暗模式、两套主题 id、字号、正文宽度、宽屏 | 最近打开（含时间） |
| 自动刷新、记忆位置、默认显示目录 | 每篇读到的位置 |
| 更新仓库、启动时检查、跳过的版本、上次检查时间 | 上次打开的目录、窗口大小、目录宽度 |
| — | `.md` 关联提示 |

判断标准很简单：**能改回来的叫设置，改不回来的是痕迹**。窗口大小属于后者 ——
重置一下窗口也跟着变，会让人莫名其妙。

- `SettingsStore.Reset(current)`：造一份默认值，再把上面那几项搬过去，最后 `Normalize`
- `SettingsStore.Backup(dir)`：重置前把 `settings.json` 复制成 `settings-<yyyyMMdd-HHmmss-fff>.bak.json`，
  只留最新 5 份。带毫秒是因为连点两次重置不能互相覆盖
- `App.ResetSettings()`：备份 → 换实例 → 落盘 → 把主题刷进资源。替换的是整个 `App.Settings` 实例，
  所以设置窗口要重新 `LoadValues()`，否则界面上还是旧值
- 重置后右下角来一条通知，带上备份文件名；顺手清掉「检查更新」的残留结果

## 顺手抽出来的东西

截图逻辑从 `MainWindow.SnapshotTo` 挪到 `WindowSnapshot.Capture(Window, string)`：
设置窗口是 `ShowDialog` 模态，主窗口的 `RenderTargetBitmap` 拍不到它，只能单独拍一份。
`--snapshot` 加 `MDVIEWER_SETTINGS_DEMO=<png>` 自检钩子，截图时把设置窗口一起打开、滚到底部拍下来。

## 验证

- `dotnet test`：169 条全过（新增 7 条：重置恢复各项默认值、保留最近/阅读位置/窗口大小、null 容错、
  备份副本、没有设置文件时返回 null、备份只留 5 份）
- `--snapshot` + `MDVIEWER_SETTINGS_DEMO` 实拍设置窗口：重置卡片排版正常，说明文字不裁不重叠

| 批次 | 内容 |
| --- | --- |
| 一 | 壳色跟随主题（36 个资源键由 4 个壳色派生）、主题 10 → 20 套、主题缩略图、三槽字体、定时换肤、无干扰、外部编辑、图片灯箱、表格排序 + sticky 表头、多文件拖入、会话恢复 |
| 二 | KaTeX 0.16.11、Mermaid 11.4.1、highlight.js 11.10.0、front matter 信息卡、导出整页 PNG |
| 三 | 标注（高亮 / 批注）、书签、TTS 朗读、文件树侧栏、单 WebView 多标签、目录过滤 |

新增文件：`MainWindow.{Reading,Annotations,Tabs,Folder,Shell}.cs`、`NoteDialog.cs`、`HexBrush.cs`，
Core 侧 `FrontMatter.cs`、`NoteStore.cs`、`VendorAssets.cs`，资源 `Assets/vendor/`（3.2MB）。

## 关键决策

### 1. 壳色只给四个，其余全混出来

0.4.x 是「浅/深两套骨架 + 换主色」，所以切主题只有按钮颜色变。要整套壳跟着走，
直觉是给每套主题写 36 个界面色，但那意味着 20 套 × 36 = 720 个色值，加一套主题成本极高。

改成：主题只声明 `Bg / Fg / Line / Card` 四个壳色，`Theme.ForMarkdownTheme()` 用 `Mix()` 派生
`TextSecondary` / `TextMuted` / `InputBg` / `BtnBg` / `HoverBg` / `NavBg` / `GridHeaderBg` … 共 36 个键。
加一套主题仍然只是「一块 CSS 变量 + 一条元数据」。

### 2. 字体写在 `<body>` 内联变量，不写进主题块

第一版把 `--font-body` 放进每个 `html[data-theme=...]` 块里。结果换主题时字体被主题的默认值盖掉，
用户选的字体白选。

改法：主题块只管配色，字体由宿主按需写到 `<body style="--font-body:...">`。
另一个坑：`:root` 里不能写 `--font-heading: var(--font-body)` —— CSS 变量在定义处就解析，
那样标题字体会被钉死成解析那一刻的默认值，用户换正文字体时标题不跟随。
正确写法是 `h1..h6 { font-family: var(--font-heading, var(--font-body)); }`，把回退留到使用处。

### 3. 三方库走「内嵌资源 → 缓存 → 按需 `<script src>`」

3.2MB 的 KaTeX + Mermaid + hljs，如果内联进每篇文档的 HTML，普通文档也要背 3MB。
改成内嵌为程序集资源，`VendorAssets.Ensure(cacheDir)` 首次运行释放到 `%APPDATA%\MdViewer\cache\vendor`，
`version.txt` 做版本标记（内容更新就改 `Version` 常量）。缓存目录本来就映射到 `https://mdviewer.tmp`，
所以释放出来的文件同源可用，CSP 只需放行这一个 origin。

`MdViewer.Core.csproj` 里 `EmbeddedResource LogicalName="vendor:%(RecursiveDir)%(Filename)%(Extension)"`，
把目录结构压进资源名。

### 4. `UseMathematics()` 必须排在 `UseEmphasisExtras()` 前面

Markdig 的扩展按注册顺序抢 token。`UseEmphasisExtras` 里有上标语法 `^...^`，
排在数学前面时 `$a^2$` 会先被吃成 `<sup>`，公式就废了。顺序反过来才输出 `<span class="math">\(...\)</span>`。
这条用探针单独验证过，不是猜的。

### 5. KaTeX 要的是裸 TeX，不是带定界符的串

Markdig 输出的公式内容是 `\(E=mc^2\)`、`\[...\]`。直接把它喂给 `katex.render()` 会报错，
`throwOnError: false` 下渲染成红色原文 —— 表现为「公式没渲染，还是那行 LaTeX」。
`katex.render` 也没有 `delimiters` 选项（那是 auto-render 扩展的）。

`app.js` 里加 `stripMathDelimiters()` 先剥掉 `\( \)` / `\[ \]` / `$$` 再交给 KaTeX。

### 6. sticky 表头不能挂在横向滚动容器上

`th { position: sticky; top: 0 }` 只在**纵向**滚动容器里有效。表格外面套了一层 `overflow-x: auto` 的
`.table-wrap` 做横向滚动，sticky 就失效了。

所以只给行数 > 18 的表加 `.table-tall`（`max-height` + 纵向滚动），让它自己在里面吸顶；
小表格本来也不需要 sticky。打印样式里要取消嵌套滚动，否则 PDF 只打出第一屏。

### 7. 多标签用单 WebView，不做多实例

实测单文档一个 WebView2 就是 7 个进程 ~426MB。开三个标签 = 1.2GB，这不是阅读器该干的事。

所以是「一个 WebView + 文档栈」：切标签 = 换内容，滚动位置按路径存在 `Settings.ScrollPositions`，
切回来再还原。代价是切换有几十毫秒渲染，收益是内存不随标签数线性增长。

### 8. 定时换肤用 `App.DarkOverride`，不碰 `Settings.Theme`

如果到点直接把 `Settings.Theme` 改成 `dark`，就再也还原不回「浅色」了（偏好被覆盖）。
`App.DarkOverride`（`bool?`）只是显示层的临时覆盖，`EffectiveMarkdownTheme` 优先看它；
出时间段就清空，回到用户原本的偏好。`ApplyAutoDim()` 里还有一条：用户手动固定了浅色/深色时不去抢方向盘。

### 9. 导出长图只能走 CDP

WebView2 的 `CapturePreviewAsync` 只截可视区域，做不出整页图。
走 `Page.getLayoutMetrics` 取 `cssContentSize`，再 `Page.captureScreenshot` + `captureBeyondViewport`。
Chromium 截图有 16384px 左右的尺寸上限，超过就整体降 `scale`（最低 0.25），宁可图小也不让整张失败。

### 10. 标注按字符偏移存 + 原文兜底重定位

渲染后的正文纯文本里存 `[Start, End)`，`quote` 存当时选中的原文。
文档改动后偏移会漂，`applyAnnotations()` 先用偏移试，对不上就用 `quote` 在整个文本里搜一次，
还是找不到就跳过那一条（不破坏排版）。所有操作都在 `TreeWalker` + `Range` 上做，
用 `<mark class="annot">` 分段包起来，跨节点的选区也能正确拆。

## 踩坑记录

- **`TreeView` 没有 `Expanded` 事件**：那是 `TreeViewItem` 的。XAML 里写 `Expanded="..."` 直接编译失败
  （`MC3072`），得 `FileTree.AddHandler(TreeViewItem.ExpandedEvent, new RoutedEventHandler(...))`。
- **`TreeViewItem` 的 `Style` 不能随手写 `Setter`**：`IsExpanded` 要在模板的 `ToggleButton` 上绑，
  直接给 `TreeViewItem` 设 `IsExpanded` 会在虚拟化时打架，展开状态由 `FileNode.IsExpanded` 双向绑定。
- **`SidebarTab` 白名单写错**：中途把页签叫 `marks`，界面用 `notes`，`Normalize()` 又把 `notes` 判为非法回落 `toc`，
  表现是「切到笔记页签，重启后又回到大纲」。白名单里同时接受 `marks`（老配置）并统一成 `notes`。
- **`FillToc()` 会覆盖页签标题**：它在文档加载时无条件写 `TocTitle = "目录"`，把「文件」/「笔记」的标题盖掉。
  改成只在「大纲」页签激活时写。
- **`Expanded` 里读盘要防抖**：文件树展开时读子目录，磁盘变动监听器又触发重建，容易互相打架。
  用 900ms 防抖 + `CaptureExpanded`/`RestoreExpanded` 保住展开状态。
- **`NoteDialog` 里把辅助方法叫 `Style(string)`** 会隐藏 `FrameworkElement.Style`（CS0108），改名 `Res`。
- **`--font-heading: var(--font-body)` 写在 `:root`**：见上面决策 2。
- **`LoadDocumentAsync` 的第三个参数**：中途加过 `restoreScroll` 参数又合并回去了，
  多标签那份代码还在传三个参数，编译报 `CS1501`。

## 发版前复查又抓到的三个问题

### 11. 页面 URL 复用同一个文件名，WebView2 拿缓存显示上一篇

`_docSeq` 是实例字段，每次启动都从 1 开始，所以渲染页永远叫 `view-1.html`、`view-2.html`……，
导航地址是固定的 `https://mdviewer.tmp/view-1.html`。**跨进程重启后 URL 和上次完全一样**，
WebView2 的磁盘缓存会直接把上次那篇 html 拿回来 —— 表现是「打开 A，显示的是上次读的那篇」。

这个 bug 只在"重启后再打开另一篇"时出现，日常切换标签（序号递增、文件名不同）反而正常，
所以很容易漏测。实测方式：连续三次启动分别打开 A、B、A，比对正文截图的哈希，
第三次之前出现过 B 的页面，与 A 的哈希一致。

修法是导航时带上 `?v=<ticks>`。就一个参数，但把"URL 相同"这个前提彻底破坏了。
本地文件每次重新读的成本可以忽略；vendor 那些静态库 URL 没变，照旧走缓存。

### 12. `SamePath` 只比字符串，正反斜杠被当成两个文件

`Path.GetFullPath` 出来的路径全用反斜杠，但配置里恢复的标签、命令行/拖放传进来的可能是
`C:/docs/a.md`。`string.Equals` 判不等，于是同一篇文档被开出两个标签，
持久化后配置里就躺着两条长得不一样的同一条路径。

`SamePath` 现在先归一化（`/` → `\`、去掉尾部多余反斜杠）再比，`RestoreTabsOnStartup`
也补了 `GetFullPath` + 去重，老配置里的脏数据进来就会被收敛掉。

顺带修正了一处语义：两个**空**路径不再算"相等"。以前 `SamePath(null, "")` 返回 true，
拿空路径去查标注时可能撞上另一条同样为空的记录。

### 13. 「3 小时前」在 UTC 机器上被说成「昨天」

`Describe()` 判断「同一天 / 昨天」时用的是 `time.LocalDateTime.Date` —— 机器的本地时区。
测试固定 `Now = 2026-11-15 10:00 +08:00`，减 3 小时是当天 07:00，本地跑没问题；
但 CI runner 是 UTC，同样的时刻换算成 UTC 是 02:00，减 3 小时落到前一天 23:00，
于是「3 小时前」这个分支不成立，掉进「昨天」。

改成按**传入的 `now` 自己的偏移**换算（`time.ToOffset(now.Offset)`），不读 `TimeZoneInfo.Local`。
这样它就是个纯函数：同一份数据在任何时区的机器上得到同样的说法，CI 也不再跟着 runner 的时区飘。
程序实际调用时 `now` 就是 `DateTimeOffset.Now`，偏移等于本地时区，用户看到的行为没变。

顺带把语义写清楚了：凌晨两点看昨晚 23 点打开的文档，说「昨天」比「3 小时前」更符合直觉，
所以跨日界落到「昨天」是有意的，测试里专门锁了一条。

这个失败是推 tag 后 CI 挂在 `dotnet test` 才暴露的 —— 本地 219 全过、CI 红，说明
**依赖机器时区/当前时刻的测试必须在 UTC 下想一遍**。

## 标签栏样式（发版前按手感调整）

第一版是「每枚标签一个圆角卡片 + 右侧 4px 间隙 + 1px 边框」，看着像一排胶囊，不像浏览器。
改成 Chrome 那种：

- 标签彼此**紧贴**，不留缝；只有当前标签有背景色（`ThemeWindowBg`，和正文同色），
  下边缘不画线，于是它和正文连成一片，视觉上是"凸出来"的那一枚
- 只圆上面两角（`CornerRadius(7,7,0,0)`），底部直角
- 相邻的两个标签**都不是**当前标签时，中间夹一条 1px、高 15px 的竖线代替留缝；
  当前标签两侧不画线
- 标签栏本身不再画底部分隔线，否则会把活动标签和正文割开

关闭按钮原来用字符 `✕`，9px，怎么调都和 12.5px 的文字对不齐 —— 字符的字形基线和字号
跟正文不是一套，换主题换字体还会变。改成两条线的矢量路径（`M 0,0 L 8,8 M 8,0 L 0,8`，
圆头端点，8×8 方框 `Stretch.None`），按几何居中。实测图标占 y=58..66（中心 62.0），
文字占 y=57..68（中心 62.5），相差 0.5px，是子像素舍入。

点击区域从 `Button` 换成 `Border`：`Button` 的模板自带 ContentPresenter 内边距，
图标在框内的位置会被模板再挤一次。换成 `Border` 后要记得 `e.Handled = true`，
否则关标签的点击会继续冒泡到标签本身，变成"关掉又切过去"。

## 已知边界

- 标注的偏移重定位只能救「小改」；整段重写过的文档里，高亮会大面积失效（跳过而不是错位到别的段落）
- TTS 依赖系统语音包，中文系统没装中文语音会念成英文腔
- 长图超 16000px 会降采样，30 页以上的文档出图会比较糊
- 文件树不做搜索和排序（目录本身就是人给的顺序），也不监听深层子目录（只监听当前展开的那一层）
